# Release Notes: `v0.1.1`

## Summary

`v0.1.1` is the first stabilized patch line for the `0.1.x` release family.

This release is important for two reasons:

1. it turns the event-log stack into a documented and published first-class feature set
2. it moves the tested Spring baseline to a security-fixed patch line

## Compatibility Baseline

- Java `25`
- Kotlin `2.3.10`
- Spring Boot `4.0.5`

## Security and Dependency Baseline Change

The release-validation baseline moved from Spring Boot `4.0.3` to Spring Boot `4.0.5`.

Why this changed:

- the previous baseline resolved to Spring Framework `7.0.5` and Spring Security `7.0.3`
- those versions are inside the affected ranges for:
  - `CVE-2026-22732`
  - `CVE-2026-22735`
- the updated baseline resolves to Spring Framework `7.0.6` and Spring Security `7.0.4`, which are the corresponding OSS fix lines

What this means for consumers:

- if your host app follows Atomic's tested baseline, upgrade to Spring Boot `4.0.5`
- if your host app explicitly pins Spring Boot `4.0.3`, upgrading Atomic alone does not move you to the fixed Spring line
- older Boot lanes may still compile in host CI, but they are no longer the recommended secure production baseline for the `0.1.1` line

## Release-Significant Changes

### Event Log Stack

The following modules are now treated as first-class published and documented modules:

- `atomic.event.log`
- `atomic.event.log.parquet`
- `atomic.event.log.iceberg`
- `atomic.event.log.duckdb`
- `atomic.event.log.spring.web`
- `atomic.event.log.ingest.api`

The official ingest API module `atomic.event.log.ingest.api` is now included in publish automation and user-facing guides.

### Relational Database Support

Official shipped SQL assets and automated verification now cover:

- `postgresql`
- `mysql`
- `mariadb`
- `oracle`

Additional note:

- `h2` remains test-compatibility only, not an official production database target

### OAuth Redirect Persistence

`atomic.app.oauth.redirect` keeps the public `store.type=entity` contract, but the shipped default path is now more explicit:

- the default shipped table path is `JPA-backed`
- custom table-name routing intentionally stays on the `legacy JDBC` path to preserve the existing host seam

### Release Automation

- the release gate continues to run Oracle-focused verification before publication
- the GitHub release now uses a curated versioned release-notes document instead of generated notes only

## Recommended Host Action

1. bump Atomic artifacts to `0.1.1`
2. move host Spring Boot baseline to `4.0.5`
3. if you use event-log HTTP ingest, switch to the published `atomic.event.log.ingest.api`
4. if you use relational app modules, align DB expectations with `postgresql` / `mysql` / `mariadb` / `oracle` support and keep `h2` as test-only
5. if you use `atomic.app.oauth.redirect`, verify whether you are on the default JPA-backed table path or an intentional custom-table legacy JDBC path
