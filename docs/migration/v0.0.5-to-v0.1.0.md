# Release Migration Guide: `v0.0.5` -> `v0.1.0`

> Draft release-scoped guide for the `v0.1.0` line.

## Who Should Read This

Read this guide if you:

- already consume any published `com.infosung:*` Atomic artifact and will bump to `0.1.0`
- want to adopt the event-log stack
- rely on the published module list in README or `docs/usage`

## Release Scope

`v0.1.0` is the first release line where the event-log stack is documented and published as a
first-class part of Atomic.

The main release-level changes are:

| Area | Release impact |
|---|---|
| Version line | all published artifact examples move from `0.0.5` to `0.1.0` |
| Event log | `atomic.event.log`, `parquet`, `iceberg`, `duckdb`, `spring.web`, and `ingest.api` are now treated as first-class published modules in docs and release automation |
| Publish automation | `atomic-event-log:ingest-api` is now part of the Maven Central publish workflow |
| Documentation | onboarding docs now include an event-log adoption path instead of only app/security/storage tracks |

## Required Action

1. Bump all Atomic artifact coordinates you use from `0.0.5` to `0.1.0`.
2. If you publish or consume the event-log HTTP ingest API, switch to the published artifact:
   - `com.infosung:atomic.event.log.ingest.api:0.1.0`
3. If your team follows README or `docs/usage` dependency snippets, refresh local setup snippets to
   the `0.1.0` examples shipped in this release.

## Event Log Adoption Path

If you are adopting the event-log stack for the first time, the recommended path is:

1. `atomic.event.log`
2. `atomic.event.log.parquet`
3. one ingress path:
   - `atomic.event.log.ingest.api` for the official Spring MVC ingest API
   - `atomic.event.log.spring.web` to bridge existing `atomic.spring.web` API logs
4. optional lakehouse extensions:
   - `atomic.event.log.iceberg`
   - `atomic.event.log.duckdb`

## Existing App/Starter Consumers

For teams already using `atomic.app`, `atomic.starter`, `atomic.storage`, `atomic.spring.web`,
`atomic.spring.security`, `atomic.spring.idempotency`, `atomic.spring.oauth2`, or `atomic.heartbeat`:

- this release-prep branch does not introduce a new mandatory property rename
- the expected host action is mainly version bump plus doc refresh
- re-run your normal integration coverage after the version bump, especially around:
  - app-module endpoints
  - security/idempotency filters
  - oauth callback flows
  - any custom exception mapping

## Checklist

- bump dependency versions to `0.1.0`
- confirm your release docs or internal templates no longer point to `0.0.5`
- if you need official ingest API publishing, use `atomic.event.log.ingest.api`
- run your normal CI/integration verification before rollout
